## 製作順序

1. **AI 三視圖**（`art/references/qingxi-day34-c/<編號>/`）：
   - 每件用工作包裡的提示詞原文，後接風格指南 5.2 固定風格段；此工具沒有負面欄，所以照 5.3 在最後加 "Avoid:" 接固定負面提示。
   - 同一段提示詞獨立生成 4 張，四張都保存。
   - 選用哪一張、為什麼、建模時和圖不同的地方，寫在各自的 `prompt.txt`，總表是 `review.json`。
   - 工具：Codex CLI 內建圖像生成，沒有回報 seed。
2. **建模**：`build_day34.py`。建模前會檢查 `prompt.txt` 已寫明選用哪一張，沒選就停。
3. **審圖**：`render_reviews.sh` 匯入**匯出的 GLB／FBX**，不是工作場景，用固定燈光渲染。只有溫石的 `_Warmth` 狀態是從 `.blend` 渲染，因為 glTF 帶不走兩張底色之間的插值。
4. **Unity 驗證**：`unity/run_unity_check.sh`（見下方）。

- **共用做法的改變**（`build_day34.py`）：
  - `rock()`：斷裂面石頭。橢球被十幾個劈理面切開，倒角後用體素重新佈線，再加大面起伏、細紋理和幾條沿表面走的裂縫。用在石壩兩岸、落石、碎石、溫石、石樁腳。
  - `moss_pad()`：石頭朝上的地方長出有厚度的苔蘚墊，邊緣厚度漸變到 0，貼著石面。
  - 石面加兩層手繪感：`MOTTLE` 是有稜角的冷暖色塊；`LICHEN` 是成群、邊緣不規則的地衣圓斑，再加細碎小斑點。
  - 管狀零件（繩、竹、綁線、蕨的葉軸）的烘焙 UV 改成「一根一條帶」，長的再切段。之前每個面各自一個小島，蒲團的貼圖有八成是空的，看起來滿是黑點。
  - 烘焙後，空白像素用最近的島顏色填滿，縮小貼圖時不會從邊緣滲出黑色。
  - 布林挖洞加了防呆：哪一刀讓網格塌掉，就換解算器重試，不行就跳過並印出來。

## 共同規格

- **原點與接地**：原點在腳印中心，底部 z = 0，前方是 Blender −Y（匯入 Unity 是 −Z）。不附地面底板。
- **LOD**：同一檔案裡每組各有 `_LOD0`、`_LOD1`（約 50%）、`_LOD2`（約 15%），例如 `UP01_Weir_LOD1`。
- **材質分組**：每件分成幾組各自烘焙，貼圖密度比較平均。碎石（`Gravel`）、草蕨（`Plants`）都和主體分開，主體才分得到足夠的貼圖面積。
- **貼圖做法**：手繪感的大塊漸層加少量筆觸，暗部偏藍紫、亮部偏暖；邊角磨亮、凹處積土、朝上的縫長苔；石頭另外加一層冷暖色塊，不會整片同一個灰。
- **碰撞**：要擋人的才附，名稱 `<ID>_Collision`；形狀是盒、圓柱或指定零件的凸包，列在 `model_info.json` 的 `collision`。
- **不刻字**：所有刻痕、炭筆畫、記號都沒有文字或數字。

### UP02 溫石（三種）

- **三種外形**分開交，各自有原點：
  - `UP02_01`：大，長 0.8 m，兩道細裂紋，旁邊一顆小石和一叢蕨；
  - `UP02_02`：中，蛋形較高，一道裂紋越過頂上；
  - `UP02_03`：小，扁平，一道短的分岔裂紋。
- **都是**半陷在濕碎石裡、磨圓的溪石，帶幾個柔和的大面；頂上有一層有厚度的苔蘚墊，石色分塊斑駁，有地衣斑；石腳一圈蕨和草。裂紋只畫在貼圖上，不切開模型。
- **`_Warmth`（0–1）**：

  | 值 | 樣子 |
  |---|---|
  | 0 | 普通溪石 |
  | 1 | 細裂紋裡透出極淡的琥珀色；石腳周圍一小圈苔蘚和草變乾、偏黃 |

  - 底色 = `lerp(Albedo, Albedo_Warm, _Warmth)`。
  - 自發光 = `Emission` 貼圖 × `0.12 × _Warmth²`。
  - `WarmthMask`：R 是裂紋，G 是乾掉的那一圈；遊戲端用自己的 shader 也可以直接讀這張。
  - Blender 裡是根節點的自訂屬性 `warmth` 驅動；GLB／FBX 匯出的是 0 的狀態，兩張底色都另外交。
  - 亮度：午後陽光下只看得到一條比石色深一點的細線，傍晚才看得出琥珀色（`UP02/warmth/` 的對照圖）。
- **`Socket_Steam`**：頂面的空物件，核心組之後可能放一縷水氣。
- **碰撞**：只有最大的 `UP02_01` 附 `UP02_01_Collision`（主石凸包），照工作包。

### UP03 水位刻痕石樁

- 方形花崗岩石樁，0.34 × 0.29 m、高 1.33 m，下面幾塊有稜角的墊腳石和碎石。
- **破損**：頂上一圈崩口；左前稜從 0.30 到 1.03 m 有四組崩片；柱腳幾處小崩面。四面都有裂縫，左前破稜那條最寬。
- **8 道橫刻痕**：長短、深淺不同（0.7–1.8 cm 深），最低一道離地 0.40 m、最高 1.25 m。
- 每道旁邊一個小圓點；最上面一道的上方刻兩道小波浪。
- 刻痕是真的凹槽，槽裡長苔；0.80–0.96 m 有一圈深色的舊水漬，往下拖出幾道水痕；表面有成群的地衣。

- **沒有任何字或數字。**
- **碰撞**：`UP03_Collision` 一個盒。

## 審圖（`art/previews/qingxi-day34-c/`）

## Unity 驗證（`art/previews/qingxi-day34-c/unity/`）

用專案固定的 Unity `6000.0.82f1`（URP）跑 [`unity/QingxiDay34Verify.cs`](unity/QingxiDay34Verify.cs)。
工作包說不改 `apps/game`，所以這個腳本放在自己的資料夾：[`unity/run_unity_check.sh`](unity/run_unity_check.sh) 跑的時候才複製進專案，跑完把它、暫存的模型副本和 URP 設定的變動都還原。

它把 FBX 和貼圖複製進專案（走遊戲的匯入預算：網格中度壓縮、貼圖最大 1024），每組建一個 URP Lit 材質，再逐項檢查。結果在 `unity/report.txt`，**119 項全部通過**：

- **尺寸**：匯入後和 `model_info.json` 一致，都在上限內，底面在 y = 0。
- **LOD**：Unity 依 `_LOD0/1/2` 名字自動建 LODGroup，涵蓋所有 LOD0 網格；三角面和 `model_info.json` 一致（50% / 15%）。
- **碰撞**：每個 `<ID>_Collision*` 都成為 MeshCollider，不渲染，範圍在模型內。
- **插槽**：`Socket_Steam`、`Socket_Smoke`、`Socket_Hand`、`UP06_LightSocket` 的高度和 `model_info.json` 一致。
- **石壩**：
  - 1.75 m、半徑 0.3 m 的玩家膠囊，在壩頂下游步道從 x −5 到 5 m 每 0.5 m 一點，21 點都站得住，閘口上的石板橋也可以走。
  - 一條 0.6 m 高的射線沿閘口往上游：堵住時打到 `UP01_Collision_Debris`；關掉 Debris 後打到閘板。
  - 閘板三個 LOD 和 `UP01_Collision_Gate` 的原點都在閘框頂；一起往上移 1.2 m 後是 1.46–3.05 m，在閘框頂之下，閘口在 0.6 m 高可以通過。
- **溫石**：`Albedo_Warm`、`WarmthMask`、`Emission` 都有匯入。
  - 驗證腳本換底色、設 Emission（0.12），模擬 `_Warmth` = 1，在午後和傍晚各拍一張。
  - Unity 的午後光比 Blender 強，裂紋的淡琥珀色在 Unity 午後比 Blender 明顯一點。
- **提燈**：紙燈是獨立發光材質；URP 裡 Emission 1.0 加點光源，看起來和 Blender 的 2.0 差不多（URP 有 bloom）。
- **平石**：碰撞頂面 0.29 m，站得上去。
- **方向**：Blender 的前方（−Y，壩的下游面）匯入後是 Unity 的 −Z。

## 和要求不同、或還沒做到的地方

- **沒有在遊戲場景裡試玩**：Unity 驗證是在獨立的檢查場景裡放模型，沒有接進上游溪谷 D3 或聽風台場景，沒有角色實際走動，也沒有手機效能實測。並排比較圖是 Blender 渲染。
- **河岸 v2 沒辦法並排**：工作包請用 `art/exports/qingxi-riverbank-v2`，但 main 上那個資料夾只有報告檔，沒有模型，所以只和 A 的上游河段、泥沙洲、聽風台並排。
- **聽風台是 FBX**：工作包寫 `qingxi-listening-terrace-v1.glb`，main 上只有 `.fbx`，比較圖用的是 FBX，匯入時沒有帶貼圖，所以是白模。
- **溫石、提燈的狀態參數**：
  - URP Lit 沒有兩張底色插值的欄位，所以 `_Warmth` 交的是兩張底色加一張遮罩，公式寫在上面。
  - 遊戲端可以用自己的 shader，或照驗證腳本的做法換底色、設 Emission。
  - FBX 不帶 Blender 的驅動，`_Lit` 也要遊戲端設 Emission 強度。
- **UP06 的提桿方向**：AI 圖是橫提，模型照尺寸上限做成直立加彎頭（見上）。
- **UP05 尺寸照工作包**：AI 圖裡的蒲團比 0.12 m 高，模型照工作包的 Ø0.55 × 0.12。
- **UP01 絞盤繩子是靜態的**：閘板拉起時不會跟著捲。
- **AI 三視圖沒有 seed**：工具沒有回報。
