# 世界物件 A：LOD0 QA 修正報告（11/05 審查回覆）

對象是 a39874bb 版本被審查的 32 件匯出檔，全部從母檔重建、重新匯出，再用匯出的 FBX 重新檢查。檢查工具是 `blender-asset-qa` 的 `qa_check`，game profile：z-fight 距離 1 mm，接觸容差 2 mm。

## 結論

| 項目 | 修正前 | 現在 |
|---|---|---|
| 整件 QA 錯誤（30 萬三角以下的件） | 292 條（審查方在 17 件上列出 113 條） | 子網格逐一掃描：非浮空錯誤 0 |
| SC04 零面積 UV 面 | Roof 7,504、Shakes 2、Timber 1 | 0（用回匯的 FBX 重跑 UV 檢查） |
| 超過 30 萬三角、被略過的 z-fight／浮空掃描 | SC03、SC04、RK05、RK06、RK10A、RK10B 整件略過 | 改成逐子網格掃描，略過 0 個子網格 |
| 子網格逐一掃描（只算大件，修正前基準） | z-fight 16、浮空 464、零 UV 2 個子網格 | z-fight 0、零 UV 0；剩下的「浮空」全部是靠在別的子網格上（整件接觸檢查懸空 0） |
| 整件接觸檢查（跨子網格） | 有 3–43 mm 縫的島：RK05 輪轂蓋、SC04 基石／柴／簷板／獸皮、RK10A／RK10B 草束、TY03 浮葉 | 懸空 0（RK06 油燈火焰原本離碟心 6 mm，已修成插進燈油 1 mm） |
| Unity `QingxiWorldPropsAVerify` | 416 PASS | 416 PASS / 0 FAIL（6000.0.82f1，最後一次重建 RK06 後重跑） |

空的錯誤清單只在「沒被略過」時才算過：最後一輪每個子網格的 `skipped` 都是 false（`qa_submesh.py` 把 `max_tris` 提高到該子網格的三角數以上）。

## 根本原因與修法（都改在 `art/source/world-props-a/build_world_a.py`）

| 現象 | 原因 | 修法 |
|---|---|---|
| 法線朝內、相鄰面繞向相反 | `recalc_face_normals` 把折疊的岩石翻面；`beam()` 用了左手座標（`s.cross(t)`），每根樑都是裡外顛倒 | `orient_out` 依島的外側重設法線；修正 `beam()` 的座標基底 |
| SC04 屋頂 7,504 個零面積 UV 面 | 草片和屋瓦（`uvkeep`）加厚的側邊沒有 UV 面積；同組裡非 `uvkeep` 零件還留著重疊的方塊 UV | `solidify_uv` 給加厚側邊展 UV；組內非 `uvkeep` 零件改為正常展開 |
| z-fight（同一位置的重複面） | `straw_shell` 的逐頂點鋸齒讓加厚背殼折到正面；複製件放在同一點（繩圈、陷阱木、流蘇、草束同一法線）；`defold` 只檢查四邊面，但匯出是三角面 | `unpleat` 把位移拉回；每組做褶面放鬆；跨零件 1.8 mm 推開（同一島剩下的褶面也推開）；最後一次刪掉 5 mm² 以下的楔形面 |
| 草、葉、碎石浮空 1–10 cm | 埋在地面以下的岩石把整件抬高（規格要求底部高度 0） | 在 z=0 切開地面，再 `settle()` 讓細節落到下面的表面 |
| 細節位移後留下 3–43 mm 縫 | 高細節位移（`hd_pass`）把承托面推開，零件沒跟著動 | 新增 `seat()`：每個沒接觸的島找最近的地面、其他零件或自己的其他島，縫在 2 mm–6 cm 之間就沿最近方向移過去（多 1 mm 咬合）。SC04 移了 35+3 個島、RK10B 34 個；發光網格（`Glow`）不動 |
| RK06 油燈火焰懸空 6 mm | 火焰底部放在碟心上方 18 mm 處，碟心燈油面在 12 mm | 火焰底部改到 11 mm，插進燈油 1 mm；`seat()` 不動 `Glow` 組，所以發光網格要在建模時就放對 |
| 石砌面共面、端蓋 z-fight | `flat_top` 把小面翻成共面褶；後牆和側牆的石層互相穿插；TY06 橫桿端蓋和輪面平齊 | `fold_safe_displace` 加 `defold()`；後牆改成卡在兩側牆之間；端蓋收進輪內 |

LOD0 三角數有少量下降（例如 SC04 2,721,180 → 2,646,969），原因都是刪掉零面積面、被遮住的重複面和背靠背面，沒有做減面。各件最新數字已更新在 `art/source/world-props-a/README.md` 和 `model_info.json`。

## 逐件表

「原始整件 QA 錯誤」是 a39874bb 版本整件跑一次 `qa_check` 的錯誤條數。超過 30 萬三角的件（RK05、RK06、RK10A、RK10B、SC03、SC04）當時 z-fight／浮空掃描被略過，所以那欄的 0 或 1 不代表沒有問題。修正前這些大件逐子網格的基準在上面的結論表。

後面幾欄都是重建後的結果：
- **非浮空錯誤**：z-fight、法線、非流形、零 UV 等，逐子網格掃描。
- **子網格單看浮空**：單看一個子網格時「沒碰到同網格其他部分」的島數。斧頭插在砧板上、瓦片放在石頭上都會被算進來，所以要看後面的整件接觸檢查。
- **著地／接觸／包在內／懸空**：`qa_contact.py` 對每個島的分類。著地＝最低點離 z=0 在 2 mm 內；接觸＝有頂點離其他島 2 mm 內，或三角面穿進其他零件；包在內＝完全在另一個封閉零件裡面；懸空＝以上都不是。

## 檢查做到哪裡

- Unity 416 個檢查只驗證結構：檔案、LOD、碰撞、樞紐點、尺寸、細節子物件。它不代替材質和風格的目視判斷，所以才附上面的並排圖和近拍。
- 沒有做手機實機效能測試。面數超出手機預算的情況照舊，交給核心組決定（見 `art/source/world-props-a/README.md`）。

## 重跑方式

```bash
blender -b --factory-startup -P art/source/world-props-a/qa_submesh.py -- <out.json> SC04 RK05
blender -b --factory-startup -P art/source/world-props-a/qa_contact.py -- <out.json> SC04 RK05
python art/source/world-props-a/lineup_world_a.py <blender.exe> buildings-SC03-SC04-RK05
blender -b --factory-startup -P art/source/world-props-a/closeup_qa.py -- --fbx <ID>.fbx --out <絕對路徑.png> --pts "x,y,z,標籤;..."
```

`--out` 要給絕對路徑。給相對路徑時，Blender 不會寫出檔案。
