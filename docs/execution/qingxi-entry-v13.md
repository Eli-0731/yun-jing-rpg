## 四項不得提前宣稱通過的品質門檻

1. **角色。** 參考圖有精細臉部、髮束、織物及玉飾，現模型只是低面數輪廓，沒有拓撲、骨架與動畫；距 AI 漫劇影像和高品質動作 RPG 仍有很大距離。下輪先完成可形變角色與操作樣片，再把高階材質、臉部與技能特效逐步加上。
2. **道路與岸線。** v12 的路緣、花草與石塊比方形灰盒進步，但近景仍重複、岩面缺紋理和陰影層次，與[道路三視圖](../../art/references/qingxi-winding-road-v1/three-view.png)差距明顯。協作者 B 專責補三種尺度的石、草叢節奏和岸線過渡。
3. **古樹。** 這次使用 `elder-tree-esg` 的原始樹幹、96 物件及 16 組葉冠，不另生樹。組裝圖裡根部已下沉，但它站在河邊與地形的相接仍要近景檢查；葉材質與樹伴畫面是否相同，仍需原端與遊戲端對照。
4. **可玩與效能。** 本次只有 Blender 預覽及瀏覽器審圖；無角色控制、流動水模擬、手機 FPS、Unity 編譯或多人驗證。要以實機的鏡頭、操作、幀時間和技能可讀性逐項證明品質，不能把電影短鏡頭的精細度直接當作持續遊玩畫質。

本輪 Blender 資產 QA 重跑後，四組均無錯誤，曲線生成的髮束、編織與流蘇已轉網格一併檢查；修正了竹籃重複提把、流蘇浮接、未套用縮放及零面積 UV。散佈組依各獨立石塊／草叢檢查，不能把調色盤式間隔當成同一模型的脫離；實際擺放接地仍需場景目視驗收。

仍保留的警告：角色 17、牌樓 9、竹籃 10、散佈組 61。靜態圓柱端蓋的多邊面、衣料初始 UV 重疊、裙內腿鞋、牌匾內裝飾及單件離展示地面的高度，暫接受為**平色原型**；不得直接用於精細貼圖烘焙、角色形變或手機量產。髮束還有兩處隱藏接面待減面。`qa-report.json` 保留全部警告，幾何檢查通過並不表示美術、骨架或遊戲品質達標。瀏覽器審圖頁七張圖片已實際載入，未進行 Unity 測試。

## Mixar 小範圍試用方法

Mixar 官方[說明](https://www.mixar.app/docs)及[開源桌面程式 README](https://github.com/Mixar-AI/mixar-app/blob/main/README.md)顯示它是 Blender 基礎的 AI 建模工具，包含多視角圖生 3D、重新拓撲、UV、骨架與匯出流程；AI 能力可能透過其託管後端或自帶金鑰使用。官方[圖生 3D 頁面](https://www.mixar.app/ai-3d)也把生成網格視為需要後續清理的起點。

先拿**我們自己的採藥籃三視圖**做一次試驗：記錄輸入圖、生成時間／額度、幾何與 UV QA、回匯到 Blender 的結果，再和本輪手作籃比較。若確實更快且拓撲、來源與成本可控，才考慮用於背景小件；角色臉、骨架和主要建築仍以可控的人工模型流程驗收。這輪未安裝或執行 Mixar，也未量到 token 節省。
