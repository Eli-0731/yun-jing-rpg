# C1｜介面概念圖三套＋版面線框

> 先讀 `00-operating-rules.md`。介面方向的完整規格在主場景工作樹的 `docs/art/ui-ux-direction-v1.md`（**整份必讀**，特別是第 2、3、5、6、11 節）。

## 1. 一句話任務

為《雲境》的遊戲介面做**三套風格不同、版面完全相同**的概念圖，加上一份精確到像素的版面線框。之後所有介面實作都以這些圖為依據。

## 2. 為什麼要做

- 目前遊戲介面是 Unity IMGUI 的灰色方塊和純文字；網頁是 Unity 白底範本。z1nnz 的原話是「不能就是簡單草率的很 AI 的那種網頁，我超級不喜歡」，要至少跟原神一樣，而且更好看。
- 三套概念圖**不是三選一**，每一套都會用到（方向文件第 11.2 節）：

| 套 | 名稱 | 用在哪裡 |
|---|---|---|
| A | 玉、紙、墨、銅 | 基礎系統；白天的河谷、古林、山城 |
| B | 極簡墨線 | 沉浸模式（HUD 降到最少）、拍照模式、過場 |
| C | 暗色絹與舊金 | 夜晚、裂靈湖、秘境、宗門大殿內 |

所以三套的**版面、按鍵位置與大小必須完全相同**，只換材質、顏色和裝飾。玩家切換時手指的位置不能變。

## 6. 三套的材質描述

| 元素 | A 玉紙墨銅 | B 極簡墨線 | C 暗色絹與舊金 |
|---|---|---|---|
| 按鍵 | 青白玉圓片，半透明，內部有光暈，邊緣切面高光；圖示是深墨線 | 只有一圈細墨線（約 2 px），中間透明；圖示是月白細線 | 深色半透明絹圓片，舊金細邊（1–2 px）；圖示是舊金線 |
| 搖桿底盤 | 玉片，邊緣有一圈淡淡的雲紋浮雕 | 一個淡墨圓圈加四個方位小點 | 深絹圓盤，舊金方位刻度 |
| 面板 | 米白宣紙，淡墨不規則邊，角落有銅包角 | 幾乎透明的淡霧白，只有一條墨線上緣 | 深色絹，舊金細框，角落有雲紋 |
| 地名 | 朱砂方印＋墨字 | 只有墨字，字下一道短墨線 | 舊金字＋暗紅小圓印 |
| 文字 | 疊在畫面上的字用月白加柔陰影；紙面上的字用深墨 | 全部用月白加柔陰影 | 舊金與月白 |
| 發光 | 只有可按的主鍵和冷卻完成時有 `jade-glow` | 幾乎不發光 | 舊金邊微光，強度低 |

**三套都要避免**：
- 大面積發光；
- 整片金框；
- 純白扁平圖示；
- 塑膠感的漸層按鈕；
- 手機遊戲常見的「立體糖果按鈕」。

## 7. 製作階段與關卡

### Stage 0｜分析
在 `PRODUCTION_STATUS.md` 寫：
- 三套各自的設計重點；
- 原神、鳴潮介面你認為好的 3 點、不好的 3 點；
- 怎麼避免「像它們」，又怎麼避免「很 AI」，例如：
  - 對稱過頭；
  - 每個角落都塞裝飾；
  - 隨機的發光粒子；
  - 錯字；
  - 看不出功能的花紋。

### Stage 1｜版面線框（不需要生圖）
- 用 SVG 手寫四張線框，照第 5 節的座標：`wireframe/01-explore.svg`、`02-combat.svg`、`03-desktop.svg`、`04-inventory.svg`。
  - 灰底、白框、每個元素標名稱與尺寸。
- 再各轉出一張 PNG（可用 Blender、Node 或任何可用的工具；做不到就只交 SVG，並寫明）。
- **關卡**：
  - 座標與尺寸和第 5 節一致；
  - 按鍵之間最少 16 px 間距；
  - 所有可按元素 ≥ 88 px（以 1080 p 計）。

### Stage 2｜概念圖（生圖）
- 每張都用線框當版面依據。生圖的提示詞要寫清楚：
  - 橫向 16:9；
  - 每個元素的位置（左下、右下弧形……）和相對大小；
  - 材質描述（第 6 節）；
  - 背景場景。
- 每套 5 張：`<套>/01-explore-mobile.png`、`02-combat-mobile.png`、`03-desktop.png`、`04-icons.png`、`05-inventory.png`。都是 1920×1080；生圖尺寸不同就照比例放，並寫明原始尺寸。
- `04-icons.png`：14 個圖示排成 7×2，每個下面附 32 px 縮小版。
  - 順序：乾坤袋、卷軸地圖、竹簡任務、羅盤設定、蒲團修煉、丹爐、藥鋤採集、雲紋跳、劍與氣流（御氣）、劍攻擊、符籙法術、玉璧格擋、殘影閃避、傳送陣（回安全點）。
- 另外 1 張 `shell/loading.png`：
  - 遠山雲霧分層插畫，中央「雲境」書法標題；
  - 一條墨線進度，下方「凝氣中… 43%　61.2 / 98.4 MB」；
  - 不能有 Unity 標誌。

### Stage 3｜檢查與修正（每張都做）
1. **版面疊圖**：把線框半透明疊在概念圖上，存到 `review/<套>-<編號>-overlay.png`。
   - 元素中心偏差超過畫面寬度 3%（約 58 px）就要修，或在 README 說明。
2. **文字檢查**：逐字核對圖上的中文。
   - 有錯字、亂碼、簡體字就重生該張，最多 2 次；還是不對，在 README 列出錯在哪裡，Claude Code 會在實作時用真的字型取代。**不要假裝字是對的。**
3. **三套一致性**：同一編號的三張（A／B／C）並排成一張 `review/compare-<編號>.png`，確認按鍵位置一致。
4. **縮小檢查**：圖示表縮到 25% 看，每個圖示還能不能認出來。
5. 每張寫一次第 6 節的 Visual Review（00 規範），Gate 給 PASS／FAIL。

## 9. 驗收標準（Claude Code 會照這張表檢查）

| 項目 | 標準 |
|---|---|
| 版面 | 三套同一編號的按鍵位置和大小肉眼一致；和線框偏差 ≤ 3% |
| 可讀性 | 手機畫面縮成 50% 時，地名、任務、按鍵標籤都還讀得出來 |
| 風格 | 三套一看就不同，但都看得出是「修仙世界的器物」，不是通用奇幻 UI |
| 原創性 | 找不到任何一個元素可以說是在抄原神、鳴潮或其他遊戲 |
| 誠實 | 錯字、做不到的地方都有寫 |

## 10. 不要做

- 不要寫遊戲程式，不要改任何工作樹。
- 不要把原神、鳴潮的截圖放進生圖參考。
- 不要為了好看把按鍵做小、移到難按的位置。
