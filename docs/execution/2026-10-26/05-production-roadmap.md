# 《雲境》製作安排與前十日新手體驗路線圖

基準日期：2026-10-25  
目前階段：M0／M1 原型  
工作單位：核心組（專案負責人＋Codex）、協助者 A、協助者 B  
節奏假設：每個工作單位每個工作日約 6 小時

## 時程怎麼理解

玩家創角後經過十個現實日才出現宗門選比，離線也計時。這不代表玩家前十日必須每天完成固定任務。系統提供能做的事情、環境線索和長期目標，玩家可以自由修煉、採集、狩獵、種植、製作、探索、交易或離線等待。

以下時程是開發工作日，不是玩家被要求上線的天數。

## 玩家前十個現實日要有的內容

### 第 0 日：創角與出生

- 自訂外觀並建立唯一修行身分。
- 伺服器一次分配真實有差異的先天天賦，不提供重抽。
- 玩家得到煉氣訣與基礎武技。
- 完整靈根、體質與靈竅先不公開，只提供可理解的身體感受與初步線索。
- 凡骨可立即用武技、採集和製作，不被留在原地等待。

### 第 1–3 日：安頓與自由探索

- 取得聚落住處、床、箱子和基礎修煉位置。
- 可在家運轉煉氣訣或練體。
- 可出門採青靈草、礦材、木材與獵取山兔。
- 可將材料出售換靈石，或保留作煉製材料。
- 第一次接觸種植、成熟保留、煉製和商販。
- 新手提示只說「可以做什麼」與操作方法，不列每日必做清單。

### 第 4–6 日：找到自己的效率差異

- 玩家開始看見自己對不同功法、元素、武技與技藝的練習速度。
- 每種技藝都可學，但長期熟練需要 20–30 個現實日以上；專注一項會明顯領先平均分配者。
- 天賦與體質改變學習效率，不直接替玩家完成材料、操作和事件。
- 解鎖第一次簡單青溪問題：斷流、枯蓮、靈獸棲地或獵物異常。
- 可合作，但單人有較長或需要工具的完整路徑。

### 第 7–9 日：準備選擇而非被迫選擇

- 玩家可在世界裡自行發現宗門人物、傳聞、功法痕跡和不同修行方式。
- 系統不要求先做完「認識所有宗門」清單。
- 玩家整理物資、修行、技藝、戰鬥與探索成果。
- 廣場公告在第十日前逐步出現，但不提前揭露完整資質。
- 玩家若幾天未上線，作物成熟後保留，十日門檻仍依服務端時間到達。

### 第 10 日：測資與宗門選比

- 創角滿十個現實日後，廣場開放完整資質測定。
- 顯示先天靈根、體質、靈竅、各路適性和目前後天成果。
- 玩家選擇申請宗門；不要求選數值最高的一個。
- 高資質可獲內門起點，平庸資質由外門或雜役起步，但都有晉升路線。
- 未立即選宗門者仍可留在大世界採集、修煉和交易。
- 入宗後取得私人洞府、床、箱子與靈田；宗門公共區可看見玩家，私人洞府為個人實例並可授權訪客。

## 第 11 日後的第一階段

- 宗門貢獻：日常委託、研究、護送、採集和事件，不以連續登入發放核心資源。
- 多技藝長期修習：煉丹、煉器、符籙、陣法、靈植、御獸。
- 師承與晉升：雜役／外門／內門依個人成果，不由玩家會長決定。
- 每週秘境：由營運後台選定該週開放數量、宗門、境界與年齡條件。
- 秘境於預告時段開放，首案為週六 20:00；不是每日固定打卡。
- 每次進入約一小時，不死可持續探索；核心修行材料仍有其他穩定路徑。
- 秘境模板和宗門資格由營運設定，隨機只作用於受控選項，不讓未測內容自動上線。

## 大世界的開發順序

世界以互相連接的區域完成，不先造一張空的大地圖。

1. 青溪聚落：出生、商販、住處、廣場、出入口。
2. 青溪林地：採藥、山兔、溪流、第一個共同事件。
3. 坊市：交易、代煉、修復和情報。
4. 太玄、玄岳、問劍三個可進入宗門據點。
5. 第一個 1–4 人秘境。
6. 丹霞、天工、御靈、玄冥宗門入口與教學。
7. 一州域三個野外區域、宗門航路與公共危機。
8. 後續州域、元嬰以上境界只在前一階段驗證後擴建。

每個區域都先完成：灰盒 → 移動／相機 → 核心循環 → 多人與存檔 → 美術套件 → 音效／光照 → 手機效能 → 盲測。不能先完成美術再補玩法。

## 每類資產的製作流程

1. 寫資產用途、觀看距離、互動、尺寸與效能預算。
2. AI 生成正、側、後三視圖；建築或地形加俯視圖。
3. 人工檢查比例、輪廓、世界風格與是否能實際建模。
4. 保存原圖、提示、日期與核准紀錄到 art/references/。
5. Blender 建低模／中模母稿，設定公尺、原點、正面與命名。
6. UV、材質、貼圖烘焙；避免無必要的材質槽。
7. 角色／生物綁骨與動畫；靜態物製作 LOD 和簡化碰撞。
8. FBX／GLB 匯出，再匯回 Blender 做尺寸與缺檔驗證。
9. 匯入 Unity，檢查 URP 材質、比例、碰撞、動畫與 LOD。
10. 在目標場景與基準手機量測，不以單獨展示視窗判定完成。

## 人力配置原則

### 核心組

- 產品決策、玩法、伺服器、Unity 整合、內容資料、測試與最麻煩的跨系統工作。
- 產生三視圖、訂效能預算、審查模型，不把規格不清的工作丟給協助者。
- 保護資產一致性、出生差異與不重複發獎規則。

### 協助者 A

- 生物、角色、骨架、動畫、LOD、UV、材質與匯出。
- 每輪只接一個可在 6 小時內驗收的資產里程碑。
- 不碰服務端發獎、數值平衡與正式場景。

### 協助者 B

- 世界灰盒、模組化場景、導航、碰撞、相機、環境線索和重建工具。
- 先做玩法尺度，再接核准的美術素材。
- 不在場景中寫私有玩法邏輯或直接改玩家資產。

## 每週管理節奏

- 週一：選一個玩家可感受到的結果，鎖定範圍和驗收。
- 週二至週四：三組在獨立檔案／分支完成工作，每天保留可測版本。
- 週五：自動測試、Blender 驗證、Unity 整合、故障情境。
- 週六：安排內部試玩或秘境營運內容預演，不要求正式玩家每日打卡。
- 週日：整理數據、裁切無效內容、排下一週；沒有證據就不宣稱完成。

## 何時可稱為「前十日完成」

必須同時達成：

- 創角、出生唯一分配、十日服務端計時與測資公開可恢復。
- 凡骨、普通、高天賦在第一小時都有實際可做的事。
- 修煉、採集、狩獵、種植、煉製、出售至少各有一條完整循環。
- 玩家離線不會毀掉作物，回來不會被連續登入懲罰。
- 第十日可以選擇宗門或暫不加入，兩者都能繼續遊玩。
- 三個宗門入口、身分起點、私人洞府床／箱／靈田能保存。
- 兩人同場、重連、重送和並行不重複發獎。
- Windows 實測通過；手機效能只有完成真機 30 分鐘測試後才可標記。
- 至少兩輪盲測證明玩家是因為想探索和成長而繼續，不是被計時器逼著留下。

用途涵蓋山兔 AI、鏡頭、遊戲手感、關卡、RPG 成長、效能和受控程序內容。這些是工作流程參考，不會取代已核准的出生差異、宗門、十日門檻與伺服器權威規則。

### 使用規則

1. 每個任務只載入 1–3 個直接相關 Skill；跨階段工作再切換，不同時讀 50 個。
2. 優先讀路由／核心 Skill，再讀一個專門 Skill 和一個 QA Skill。
3. Skill 指示若與 AGENTS.md 或使用者已確定規則衝突，以本專案規則為準。
4. 外部 Skill 中的下載、版本升級、服務登入或部署命令都要先對照本專案版本和憑證規則。
5. 安裝 Skill 不等於安裝 Blender 外掛、Unity 套件或雲端服務；工具本身仍需獨立驗證。
6. 每季檢查來源提交、授權和不再使用的 Skill，避免長期累積無效流程。
