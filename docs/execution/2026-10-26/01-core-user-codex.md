## 本輪要交付的結果

核心組要把「看見山兔、追蹤、狩獵、取得材料、回村出售」定義成一條可測試的完整玩法，完成資料定義、服務端規則、自動測試和 Unity 串接介面。這一輪不追求最後畫面，也不把等待時間當作玩法。

完成後，協助者 A 的山兔資產和協助者 B 的狩獵灰盒能接到同一套規則；即使 Unity 尚未通過授權與編譯，服務端的獎勵、重送與並行規則也要先能自動驗證。

## 玩家實際會做什麼

1. 玩家從青溪聚落出發，自由選擇修煉、採藥或往林地探索。
2. 林地以腳印、啃食過的草與短促聲音提示山兔活動，不在畫面中央強制顯示任務箭頭。
3. 玩家靠近後，山兔由閒置轉為警戒；再靠近或攻擊時逃往附近掩體。
4. 玩家可用基礎武技或煉氣訣的初階攻擊狩獵。失手只消耗時間或少量體力，不扣出生天賦或永久物品。
5. 山兔死亡後，由可信伺服器決定一次獎勵。首版固定掉落 rabbit-meat × 1，並以機率掉落 rabbit-hide × 1；機率值放在版本化內容資料，不寫死於 Unity 畫面程式。
6. 玩家回村向材料商販出售，換取少量靈石；也可保留材料供日後烹飪或製作。
7. 同一隻山兔即使重送死亡訊息、兩人同時命中或區域程序重啟，也只能結算一次。

## 規則邊界

### 即時區域伺服器負責

- 山兔的位置、狀態、生命、有效命中與死亡。
- 玩家與山兔的距離、攻擊冷卻和基本合法性。
- 產生唯一 encounterId、enemyInstanceId、deathId。
- 將已確認死亡提交給遊戲 API；客戶端不能自行宣告獲得幾件物品。

### 遊戲 API 負責

- 依內容版本計算可領取物品。
- 使用 deathId／rewardId 做冪等結算。
- 在同一資料庫交易中寫入物品帳本與結算收據。
- 出售時再次檢查持有數量、綁定狀態、售價版本與 requestId。
- 成功持久化後才回覆客戶端成功。

### Unity 客戶端負責

- 顯示山兔、動畫、命中特效、掉落提示及出售介面。
- 對本機玩家即時播放揮擊與預備動作。
- 收到伺服器結果後修正生命、死亡與獎勵顯示。
- 不保存權威物品數量，也不能以本機時間加速重生。

## 必須通過的自動測試

1. 一個有效死亡只增加一份固定掉落。
2. 相同 deathId 重送時回傳原收據，不再增加物品。
3. 兩個請求並行結算同一隻山兔，只有一個建立獎勵。
4. 不存在、過期或不屬於該區域的死亡不能發獎。
5. 客戶端傳入自訂掉落數量時被拒絕或完全忽略。
6. 出售一件材料只增加一次靈石並扣除一次物品。
7. 相同 requestId 但不同出售內容回報冪等衝突。
8. 沒有足夠物品不能出售，失敗不改變帳本。
9. 兩位玩家同時參與時依伺服器參與紀錄結算，不能靠最後一擊拿走別人的既有獎勵。
10. 既有 45 項測試全部維持通過。

## 核心組的美術與建模責任

本輪不重做山兔；使用協助者 A 交付的 QMountainRabbit 生產版。核心組負責審查比例、輪廓、動畫可讀性、材質數、LOD 和碰撞，以及決定狩獵區需要哪些環境模組。

下一批世界資產依序為：

1. 青溪常見樹木組：幼樹、成樹、枯木，各一件並做枝葉變體。
2. 聚落民居模組：牆、屋頂、門窗、柱廊、床與箱子。
3. 溪流模組：直段、彎段、淺灘、瀑差、岸石；水面用 Unity 材質與網格。
4. 林地地表：草叢、藥草叢、兔洞、足跡貼花、倒木與岩石。
5. 道路與指引：石徑、木橋、宗門公告牌、商販攤位。

每一件自行製作資產的順序固定為：AI 三視圖／材質方向圖 → 人工檢視 → 保存到 art/references/<asset>/ → Blender 母稿 → UV／材質 → LOD／碰撞 → FBX/GLB 回匯驗證 → Unity 匯入驗證。不得跳過三視圖。
