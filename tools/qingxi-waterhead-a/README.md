## 水與土地分離、碰撞、接口

- **水是獨立節點**：每段河床的 GLB／FBX 分成 `<key>_LOD0`（土地與石頭，烘焙）、`<key>_Water`（水面）、`<key>_Foliage`（草葉）。
  - 水面的 UV 是「V＝沿河道往上游的公尺數」，流動 Shader 可以直接沿 V 捲動。
  - 展示裡清泥沙後上升的就是 `_Water` 節點本身，土地不動。
- **水接口 `SOCKET_*`**：模型裡的空物件，+Y 是水流方向，同時列在 `*_model_info.json` 的 `sockets`。
  - A01 河段：`SOCKET_upstream`／`SOCKET_downstream`；源頭收尾件是 `SOCKET_spring`。
  - A02 古石槽：`SOCKET_inlet`／`SOCKET_outlet`／`SOCKET_leak`（破口）。
  - 導水方案要把水接進石槽，就是把河段的接口接到石槽的 `SOCKET_inlet`，和 B 組水利套件的接法相同。
- **碰撞殼 `<key>_Collision`**：A02、A03、A06、A09、A12 附凸包碰撞殼，不渲染。
  - 展示載入時把殼的地面輪廓轉成多邊形牆，玩家停在石槽、石頭真正的外緣，不再用估計的圓。
  - 規則見 `investigation.mjs` 的 `polyDistance`，有測試。
  - 碰撞檢視（主控台 `__wh.setPlan(true); __wh.colliders(true)`）畫出紅色碰撞多邊形與青色接口箭頭。

## 玩家會遇到什麼

**三種缺水跡象**（記入線索簿）：

| 線索 ID | 在哪裡 | 看到什麼 |
|---|---|---|
| `cracked_sluice` | 右岸兩段古石槽 | 側面裂口與末端斷裂，水漏到岸上（A02 兩種破口，看任一處都算） |
| `silt_buildup` | 河道裡三處 | 泥沙矮壩、沿岸沙嘴、倒木雜物壩（A04 三種堆形，看任一處都算） |
| `nursery_tracks` | 右彎內岸的濕泥 | 大小三組爪印走向水邊（A07） |

**環境提示**（只回應文字，不算答案）：
- 示跡石（A06）：兩道水位線。
- 水位尺（A09）：舊水位綁繩在 0.86 m，現在只到 0.30 m，和岸上乾痕是同一組數字。
- 水脈共鳴石（A12）：走近時紋路變亮、發出嗡鳴，沒有箭頭。

**兩種場景變化**（資料狀態在 `investigation.mjs`，畫面只是顯示）：
1. **清理泥沙前後**：看過主泥沙堆後，再按一次觀察可以「扒開一點泥沙」。
   - 泥沙堆會換成清理後的模型（`A04_SiltBar_cleared`），下游的水面在幾秒內上升。
   - 這只是試試看，不是正式處理，也不會寫進交接資料。
2. **育幼側警戒**：走進育幼足跡周圍 4.2 m，會聽到低低的嗚聲，畫面邊緣泛琥珀色，並提示放輕腳步；退出後就停止。
   - 這是非戰鬥警戒，不扣血、不會中斷調查。

**繞路與通行**：
- 三處淺灘（A08 三種踏面）可以過河，也可以直接涉過淺水改走對岸。
- 倒伏竹（A10）擋住右岸部分視線，但留有缺口可以穿過；它不會把鏡頭推近。
- 觀測亭殘基（A11）可以走上去，在上面按觀察會翻開手札，比較已找到的跡象。

**手札**：
- 任兩條線索 →「可以回去商量了」；三條 →「找齊三種原因」。
- 手札會列出看到的跡象，並說明下一步：回水工場找工匠，決定先清泥沙、修古水路，還是避開育幼處。這段就是 B 組導水方案的入口。
- 畫面上不顯示程式資料；交接 JSON 只在網址加 `?dev=1` 時顯示。

**回入口與重新調查**：回入口（R）會保留線索簿；「重新調查」會清空線索簿，並把泥沙放回原處。

**擋路與邊界**：右彎外側岩壁、石槽、陣基、峽口大岩、源頭亂石堆、水位尺、共鳴石、竹子屏障都會擋住，河段外不能走。

## 河段組裝

- 由 A01 五種形體串成約 29.5 m，接口數據取自 `art/exports/qingxi-waterhead-a/A01_*_model_info.json`，同一形體不相鄰：
  - 走法 A（預設）：直段 → 左彎 → 收窄 → 右彎 → 源頭收尾件
  - 走法 B（`?route=b`）：直段 → 右彎 → 收窄 → 左彎 → 源頭收尾件
- 道具依模組種類擺放，兩種走法都能完成同一條調查。
- 淺灘（A08）與水位尺（A09）用河床塊的座標系：原點在河床塊底面，放置方式和 A01 模組相同。

## 交接給 B／C

`observations.example.json` 是本機 fixture，格式同 `Investigation.toJSON()`：

```json
{ "schema": "qingxi-waterhead-a/observations@1", "observationIds": ["cracked_sluice", "silt_buildup"], "order": ["cracked_sluice", "silt_buildup"], "verdict": "discuss" }
```

- `observationIds` 依固定順序（`cracked_sluice`、`silt_buildup`、`nursery_tracks`）列出看過的跡象。
- `order` 是實際發現的順序。
- `verdict` 為 `null`、`discuss` 或 `full`。
- 清理泥沙只是場景試看，不會出現在交接資料裡；正式的處理結果是 B 組的 `outcomeId`。

## 審查用畫面

| 呼叫 | 內容 |
|---|---|
| `__wh.setPlan(true)` | 正交俯視圖，標出模組與所有道具的變體 ID |
| `__wh.colliders(true)` | 再疊上模組接縫（白線）、碰撞多邊形／圓（紅）、水接口箭頭（青）、育幼警戒範圍（黃） |
| `__wh.eye(true)` | 1.7 m 眼高視角（替身隱藏） |
| `__wh.highWater(true)` | 舊高水位 0.86 m 的水面，看淺灘在水下的狀態 |

`capture.mjs` 會輸出完整流程截圖、兩種走法的俯視圖、接縫／碰撞圖、眼高圖、淺灘露出／淹沒對照與手機橫向畫面。`record.mjs` 會錄一段即時實玩，再用 `art/source/qingxi-waterhead-a/encode_video.py` 轉成 MP4。兩者都需要另裝 `playwright-core`。
