# 正式接線意圖與 UI 狀態

作者：Eli-0731／Codex。此檔僅交接契約草案，沒有新增 API 路由，也沒有提交正式物品變更。頁面匯出的 `qingxi-return-intent/v1` 中 `sampleReference` 為固定演示 ID，不是正式物品 ID；`mode` 固定 `local-demo`，每筆 `requiresServerValidation` 固定 true，不包含數量、報酬或可自報的完成條件。

| UI 狀態／事件 | 本機展示 | 未來服務端驗證 |
|---|---|---|
| 未選樣本 | 三個去向可點，提示先選樣本 | 不提交請求 |
| 選樣本 | 顯示固定來源、用途及目前位置 | 實際物品 ID／綁定、擁有權、可用狀態須由服務端快照提供 |
| 保存／留待煉製 | 將該樣本的唯一去向改為所選值 | 服務端驗證可用物品實例、目標容器／保留權限、角色及容器距離、當前版本；不能接受前端自報數量 |
| 交委託（展示） | 只移到封條盒；不完成委託或給獎 | 僅代表查看／規劃意圖；正式交付必須另由核心組既有委託規則檢查資格、材料、綁定與距離，同一交易扣物並決定收據 |
| 重複點同一去向 | 沒有新增紀錄、版本或樣本 | 以玩家、requestId、動作及 payload hash 綁定；相同重送回原收據，異內容拒絕 |
| 取消最近一次選擇 | 回復前一個去向；再取消無效 | 正式取消需引用服務端操作收據並由服務端判定是否仍可逆；已消耗、已交付或已結算不得在前端復原資產 |
| 重載／兩裝置 | 本機 localStorage 是展示備忘；不保證跨分頁決策不互相覆寫 | 讀服務端快照；並行更新需版本／鎖與唯一交易，不以本機紀錄作資產事實 |
| 手札開闔、白日／傍晚 | 僅顯示狀態 | 不產生資產請求 |

核心組未來可將意圖轉為 `{requestId, action, inventoryInstanceId, targetId, expectedVersion}`；這是內部草案，不是可直接呼叫的正式端點。`requestId` 重試時保持不變，服務端以收據和原子交易解決重送、並行及重啟，前端只有收到服務端結果才能顯示正式去向。網路狀態未知時保留待確認意圖，不自行認定物品已扣除或發獎。

本機展示一份樣本是一筆固定身分；畫面的「1 份」不是遊戲材料數量。三份樣本總數恆為三，任意去向皆可、可保留未整理狀態，沒有每日清單、時長門檻或強制委託。
